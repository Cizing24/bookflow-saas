# BookFlow 權限矩陣

| 操作                                           | Owner    | Admin    | Staff                          | 持有私人管理連結的顧客                |
| ---------------------------------------------- | -------- | -------- | ------------------------------ | ------------------------------------- |
| 店家總覽、服務目錄與營業時間                   | 同店     | 同店     | 同店公開目錄＋自身員工資料     | 僅公開預約頁                          |
| 日／週行事曆、預約詳情、異動紀錄               | 同店全部 | 同店全部 | 僅明確綁定的自身員工預約       | 僅 Token 對應預約，不含稽核與顧客個資 |
| 改期／變更服務與人員                           | 同店全部 | 同店全部 | 自身預約，不可轉給其他員工     | 自身預約、原服務與員工 UI，截止時間內 |
| 取消                                           | 同店全部 | 同店全部 | 自身預約（新 booking API）     | 自身預約，截止時間內                  |
| 完成服務／標記未到場                           | 同店全部 | 同店全部 | 自身預約                       | 禁止                                  |
| 服務、人員、營業時間、排班、預約間隔與提前政策 | 可編輯   | 可編輯   | 唯讀自身班表，無寫入權限       | 禁止                                  |
| 自助取消／改期截止設定                         | 可編輯   | 禁止     | 禁止                           | 僅知悉適用政策                        |
| 成員角色、新增移除與員工帳號綁定               | 可編輯   | 禁止     | 禁止                           | 禁止                                  |
| 顧客名冊、搜尋、次數與歷史                     | 同店全部 | 同店全部 | 禁止；僅自身預約內必要聯絡資料 | 禁止                                  |
| Dashboard 統計                                 | 同店全部 | 同店全部 | 僅自身預約計算                 | 禁止                                  |
| Outbox、Email 預覽與私人連結                   | 同店全部 | 禁止     | 禁止                           | 僅自己收到的信                        |

每次管理 use case 使用 Better Auth 伺服器 Session 查詢 `[tenantId,userId]` Membership；URL 的 tenantId 僅為查找目標，不是授權。所有關聯與查詢包含租戶範圍。STAFF 以 Membership.staffId 綁定，不依使用者自行傳入 staffId 決定身分；未綁定時查無任何工作預約，不能藉由 query filter 擴大權限。跨店資源 ID 不可連結，DB 複合 FK 再次防護。

公開建單與查看公開可用時段不需帳號；異動已存在預約必須有管理 Session 或 256-bit 私人 Token，姓名、Email、Booking ID 都不是授權憑證。顧客的 input id 會被伺服器替換成 Token 對應 ID。

Owner 可加入已註冊帳號，設定 ADMIN / STAFF 與同店員工綁定，或移除非 Owner 成員。一般 API 不能建立／降權／移除 OWNER；帳號移轉擁有權須另訂流程。角色或綁定異動後的下一次請求立即重讀 Membership，Booking 異動更在 Tenant lock 內重驗。既有已開始的唯讀查詢具有該次授權的快照，不宣稱可收回已傳給瀏覽器的資料。

舊 `/cancel` endpoint 保持 OWNER / ADMIN 限制以維持前階段契約；新 `/booking` endpoint 支援 Staff 自身工作與完整狀態機。不存在只靠隱藏按鈕的授權。

驗證：單元測試涵蓋完整狀態轉換矩陣；整合測試只注入 Session identity，使用真實 PostgreSQL Membership、水平／垂直／跨租戶拒絕、綁定及 Outbox；桌面／手機 E2E 使用真正 Better Auth Session、API 401 / 403 與營運操作。DB 超級使用者、應用原始碼執行權限與被竊取的私人 Token 不在租戶 API 的防護範圍內。
